# Прототип бота «Успевайка»

Telegram-бот с витриной (Mini App): меню по категориям, карточки блюд, корзина, оформление заказа с адресом, днём и интервалом доставки. Заказ приходит в чат менеджеров, статусы меняются кнопками, клиент получает уведомления. Остатки и стоп-лист ведутся командами.

## Что внутри

| Файл | Что это |
|---|---|
| `bot.py` | Бот (aiogram 3) + веб-сервер, который раздаёт витрину, `menu.json`, фото и иконки |
| `admin.py` | Админ-панель: API меню, остатков, фото, заказов и статистики |
| `webapp/index.html` | Витрина: открывается внутри Telegram по кнопке «🛒 Меню и заказ» |
| `webapp/admin.html` | Панель управления: `/admin` |
| `webapp/img/` | Фото блюд (WebP, 4:3 + `@2x` для retina), логотип, иконки |
| `menu.json` | Меню, цены, остатки, условия доставки. **Точные цены — там, где `price_source: "channel"`; остальные примерные** |
| `orders.db` | База заказов SQLite (создаётся сама) |
| `tests/` | Проверки логики и интеграционный прогон бота через поддельный Bot API |

## Что в витрине

- Категории с иконками, поиск по названию и описанию, скелетон при загрузке.
- Карточки с фото (WebP + retina), метками «Хит», «Новинка», «Предзаказ», «Осталось N шт».
- Шторка блюда: фото, описание, вес, упаковка, способ приготовления, КБЖУ, хранение.
- Корзина с количеством, сохранение в `localStorage`, сумма и порог бесплатной доставки.
- Заказ всегда отправляется на сервер (`POST /api/order`): он атомарно списывает остатки, знает номер заказа и отвечает понятной ошибкой. Внутри Telegram при недоступности сервера есть запасной канал — `sendData`, но только после проверки лимита 4096 байт (у метода больше нельзя, и раньше это теряло заказы). Обе ветки идут через один код (`place_order`) с одинаковыми проверками и списанием остатков.
- Клиент опознаётся по подписанному токену в ссылке: бот формирует кнопку «🛒 Меню и заказ» для каждого чата отдельно (`…?u=<id>.<подпись>`), витрина передаёт токен с заказом, сервер проверяет HMAC. Это работает и на iOS, где Telegram часто не передаёт витрине `initData` вовсе. Если токена нет, используется `initData` (из SDK или из хэша адреса) с проверкой подписи ключом бота. Подделать ни тот, ни другой нельзя; без опознания заказ принимается и помечается «с сайта».
- Оформление: контакты, **район доставки** (стоимость считается на сервере), **день** (только дни из расписания), интервал, оплата, комментарий.
- Светлая и тёмная тема, фирменные цвета (оливковый и коралловый), шапка с логотипом.

## Фото блюд

Фото лежат в `webapp/img/<id блюда>.webp` (и `@2x.webp`). Путь указывается в `menu.json` в поле `"image"`. Источники: снимки из канала «Успевайки» и фото под свободной лицензией (Wikimedia Commons, TheMealDB) — для прототипа. Перед публикацией замените на собственные фото блюд: достаточно положить файл с тем же именем.

## Доставка и дни

В `menu.json` → `settings`:

- `delivery_zones` — районы: `title`, `free_from` (порог бесплатной доставки), `price`, опционально `min_sum`.
- `delivery_days` — дни недели доставки; бот и витрина предлагают и принимают только их.
- `delivery_days_ahead` — на сколько дней вперёд показывать окно.

Стоимость доставки и минимальная сумма района **пересчитываются на сервере** — значения из витрины не принимаются на веру.

## Панель управления

Админка живёт на том же сервере: `http://localhost:8080/admin`. Вход двумя способами:

- **В Telegram** — кнопка **«🛠 Админка»** в главном меню (видна только id из `ADMIN_IDS`) или команда `/admin`. Ссылка несёт подписанный токен админа со сроком 30 дней: на iOS Telegram не передаёт витрине `initData`, и без токена панель не пустила бы даже своего. Токен убирается из адреса после загрузки страницы и передаётся заголовком `X-Admin-Token`.
- **В браузере** — по паролю `ADMIN_PASSWORD` из `.env`. Если пароль не задан, вход по паролю выключен; тогда работают только ссылки с подписанным токеном, которые присылает бот по `/admin` (и ссылка «Добавить блюдо» из чата). Голый адрес `/admin` вне Telegram в этом случае попросит пароль, которого нет, — поэтому пользуйтесь ссылкой из бота.

Пароль лучше держать длинным; сессия — подписанная HttpOnly-кука на 12 часов, после 8 неудачных попыток вход с адреса блокируется на 5 минут.

**CSRF-защита.** Кука сессии `SameSite=Lax` уезжает с переходом по ссылке из чужого сайта, поэтому все изменяющие запросы (POST) требуют заголовок `X-CSRF-Token`. Токен выдаёт `GET /api/admin/csrf` (и `POST /login`, и `GET /session`); он подписан секретом сервера и привязан к пользователю, живёт сутки — переживает перезапуск бота и не требует хранилища. Без токена или с чужим токеном — `403`. Чтение (`/menu`, `/orders`, `/stats`) токена не требует.

### Уведомления о заказах

О новом заказе бот пишет в `ADMIN_CHAT_ID` — с кнопками статусов прямо в сообщении. Источники одинаковы: витрина в Telegram, сайт, панель управления («Заказ по телефону»). Если `ADMIN_CHAT_ID` не задан или недоступен, уведомление уходит в личку первому id из `ADMIN_IDS`. Если Telegram недоступен совсем, заказ всё равно сохраняется в базу и виден в админке.

Сообщение ограничено лимитом Telegram в 4096 символов. Если состав не влезает (очень длинные названия, много позиций, длинный комментарий), бот сокращает список позиций и дописывает «…и ещё N поз. — полный состав в админке», но шапку, контакт, сумму и статус сохраняет. Без этого Telegram отклонял сообщение, и менеджер не видел заказ вовсе.

Сообщение о заказе живёт как «карточка»: его `message_id` сохраняется в базе, и при смене статуса или правке состава карточка обновляется на месте, а не шлётся новым сообщением. Поэтому в чате один заказ — одно сообщение. Если чат недоступен, обновление молча пропускается: заказ при этом не теряется.

**Клиент тоже получает уведомления.** При смене статуса (принят, собран, в пути, доставлен, отменён) бот пишет клиенту в личку — и при смене из чата менеджеров, и из админ-панели. Сообщение уходит на Telegram id, с которым оформлен заказ; у заказов «с сайта, без Telegram» чата нет, поэтому им ничего не отправляется и менеджер связывается по телефону.

Что умеет:

| Раздел | Возможности |
|---|---|
| Меню | добавить, изменить, удалить блюдо; поставить на стоп и вернуть в продажу с остатком; загрузить фото (кроп 4:3, WebP + retina делается сам); управлять категориями |
| Заказы | список с фильтрами по статусу, детали, смена статуса (клиенту уходит уведомление, при отмене возвращаются остатки). Сюда же попадают заказы, оформленные в браузере |
| Статистика | заказы и выручка за сегодня и всего, средний чек, выручка по дням, топ блюд, разбивка по статусам |
| Настройки | город, телефон, минимальный заказ, дни и интервалы доставки, способы оплаты, районы с порогами |

Все изменения `menu.json` идут через тот же `asyncio.Lock`, что и заказы, — остатки не разъедутся при одновременной продаже.

## Быстрый запуск прототипа

```bash
cd bot
./start.sh
```

Скрипт сам найдёт окружение, спросит токен, адрес витрины и id менеджеров (если их нет в `.env`), подскажет команду для туннеля и запустит бота.

**Порт занят.** Если предыдущий запуск не завершили, скрипт не падает стектрейсом `address already in use`, а показывает, кто держит порт, и предлагает остановить его:

```
Порт 8080 занят: процесс 4126718
  .venv-linux/bin/python bot.py
Это прежний запуск бота из этой папки — он работает со старым кодом.
Остановить его и запустить заново? [Д/н]
```

Свой бот из этой папки останавливается автоматически (сначала `SIGTERM`, затем `SIGKILL`, если не завершился). Чужой процесс не трогается — скрипт выходит и предлагает `kill <pid>` или `PORT=8090 ./start.sh`.

**Без терминала** (автозапуск, systemd) скрипт не спрашивает и не зависает: отсутствующие переменные пропускаются с подсказкой «задайте в `.env`».

Введённые значения **запоминаются в `.env`** (права `600`, файл исключён из git) — второй раз их вводить не придётся. Чтобы поменять токен: отредактировать `.env` или удалить строку `BOT_TOKEN=` и запустить снова.

Рядом в отдельном терминале нужен HTTPS-туннель — Telegram не открывает витрину по http:

```bash
cloudflared tunnel --url http://127.0.0.1:8080     # на Debian/Ubuntu: apt install cloudflared
```

Он выдаст адрес вида `https://xxxx.trycloudflare.com` — его и нужно указать в `WEBAPP_URL`.

Только витрина, без бота: `./start.sh --web-only`.

## Запуск вручную

1. Создать бота у [@BotFather](https://t.me/BotFather) → `/newbot`, скопировать токен.
2. Скопировать `.env.example` в `.env` и вписать `BOT_TOKEN`.
3. Установить зависимости и запустить:

```bash
cd bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python bot.py          # или: PORT=8080 .venv/bin/python bot.py
```

На Windows: `.\.venv\Scripts\pip install -r requirements.txt` и `.\.venv\Scripts\python bot.py`.

Витрина сразу доступна в браузере на http://localhost:8080 (в демо-режиме вместо отправки показывает, что получит бот). Проверка живости: `GET /healthz`.

4. Telegram открывает витрину только по **HTTPS**. Для теста на своём компьютере — туннель [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/):

```bash
cloudflared tunnel --url http://localhost:8080
```

Он выдаст адрес вида `https://xxxx.trycloudflare.com` — вписать его в `WEBAPP_URL` в `.env` и перезапустить бота.

5. Чат менеджеров: создать группу, добавить туда бота, написать `/id` — вписать chat id в `ADMIN_CHAT_ID`. Свой user id (команда `/id` в личке с ботом) вписать в `ADMIN_IDS`. Перезапустить.

## Настройки

Все переменные — в `.env` (образец в `.env.example`):

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота; без него работает только витрина |
| `WEBAPP_URL` | https-адрес витрины |
| `ADMIN_CHAT_ID` | чат, куда падают заказы |
| `ADMIN_IDS` | id менеджеров через запятую; им доступна админка по `/admin` |
| `ADMIN_PASSWORD` | пароль для входа в `/admin` из браузера; если пусто — вход по паролю выключен |
| `PORT` | порт веб-сервера, по умолчанию 8080 |
| `MENU_PATH` | путь к `menu.json`, по умолчанию рядом с `bot.py` |
| `DB_PATH` | путь к базе заказов, по умолчанию рядом с `bot.py` |
| `TELEGRAM_PROXY` | прокси для запросов к Telegram, например `http://127.0.0.1:20172`. Если не задан, берётся `HTTPS_PROXY` из окружения |

### Если бот не отвечает на /start

`aiogram`/`aiohttp` **не читают** `HTTPS_PROXY` сами — в отличие от `curl`, они ходят напрямую и виснут до таймаута, если интернет требует прокси. Признак: в логе `TelegramNetworkError`, `Request timeout error` или молчание после `Start polling`. Решение — задать `TELEGRAM_PROXY`:

```bash
TELEGRAM_PROXY=http://127.0.0.1:20172 ./start.sh
```

`start.sh` подхватывает `HTTPS_PROXY` автоматически, так что обычно достаточно запустить его из того же окружения. При старте бот пишет, через что идёт: `Запросы к Telegram идут через прокси …`. Для прокси нужен пакет `aiohttp-socks` (в `requirements.txt`).

## Как пользоваться

**Клиент:** `/start` → «🛒 Меню и заказ» → выбрал блюда → «Оформить» → заказ ушёл. Внизу ещё «📋 Мои заказы», «🚚 Доставка и оплата», «📞 Связаться».

**Менеджер** (в чате заказов): кнопки «✅ Принят → 📦 Собран → 🚗 В пути → 🏁 Доставлен» или «❌ Отменить» (остатки вернутся). Команды:

- `/stock` — все блюда и остатки
- `/orders` — активные заказы
- `/stop тефтели` — убрать в стоп-лист
- `/set сырники 15` — задать остаток

Меню, цены, фото и условия доставки правятся в `menu.json` (фото: поле `"image": "static/имя.jpg"`, файл положить в `webapp/`). Изменения видны клиентам сразу, перезапуск не нужен.

## Что проверено

Цены, суммы и остатки бот пересчитывает сам по `menu.json`; значения из витрины (`total`, `price`, количество) не используются. Списание остатков идёт одной операцией под блокировкой — два одновременных заказа не продадут одно блюдо дважды. Остатки возвращаются при отмене и при сбое записи в базу.

Проверки запускаются без сети и без токена:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

125 проверок: логика заказа и остатков, админ-панель и CSRF, приём заказа с сайта и `initData`, валидация телефона и дат, плюс интеграционный прогон настоящего aiogram-бота против локального поддельного Bot API (polling, отправка заказа менеджеру, смена статусов, возврат остатков, отказ не-админу).

## Ограничения прототипа

- Витрина открывается кнопкой под полем ввода (так Telegram позволяет передать заказ боту без отдельного сервера API). Кнопка «Меню» у канала и онлайн-оплата — следующий шаг.
- Любой открывший витрину может отправить заказ с произвольным адресом — это нормально для доставки, но злоупотребления (флуд заказами) ограничены только паузой 5 секунд между заказами одного пользователя.
- При старте бот делает один вызов `getMe`. Если токен неверный, он пишет понятную ошибку и продолжает отдавать витрину (без polling) — так видно, что дело в токене, а не в сети.
- Нет онлайн-оплаты, бонусов, рассылок и «сообщить о поступлении» — это вторая очередь.
- SQLite подходит для одного процесса. Если ботов станет несколько, понадобится общая база.
- Для работы 24/7 нужен VPS (бот + HTTPS-домен) вместо туннеля на компьютере.
